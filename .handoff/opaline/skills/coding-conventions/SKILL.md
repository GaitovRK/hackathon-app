---
name: coding-conventions
description: How code is written in Opaline (Next.js web + Expo iOS app + Prisma). Use before implementing any agent:dev issue.
---
- Read `AGENTS.md`, `CLAUDE.md`, `mobile/AGENTS.md` for iOS work, and for UI `docs/design-style.md`.
- **Next.js 16** has breaking changes: read the relevant guide in `node_modules/next/dist/docs/` before using a Next API. **Expo SDK 57** (`mobile/package.json`): check the versioned docs at docs.expo.dev before using an Expo API; install native packages with `pnpm expo install` inside `mobile/`.
- pnpm only. Web: routes in `src/app/`, components grouped by type in `src/components/<Group>/`, hooks by domain in `src/hooks/<domain>/`, server logic in `src/lib/<domain>/`, API calls via RTK Query (`src/store/api.ts`). iOS: routes in `mobile/src/app/`, the same grouping under `mobile/src/`, RTK Query in `mobile/src/store/api.ts`. Shared types for the API in `src/types/api.ts`.
- Reuse before adding: check `src/components/`, `mobile/src/components/`, hooks and `src/lib/`. Tokens only — no raw colors/sizes in components (Tailwind theme tokens on web, `useColors()` / `radius` / `spacing` on iOS).
- Same feature on both platforms when the issue says "Both"; keep names and behavior the same.
- Copy: every string in `messages/en.json` + `messages/tr.json` (web) and `mobile/messages/{en,tr}.json` (iOS); the `messages.test.ts` tests check the keys match.
- API routes: validate input with zod, check the session user owns the resource, return typed JSON. The iOS app sends `Authorization: Bearer`; both auth paths must keep working.
- Credits only through `src/lib/credits/` (charge, refund, grant are transactional and idempotent). Prices / credit amounts in `src/lib/credits/products.ts`. Never call fal or other paid APIs in tests or scripts you run; mock `@fal-ai/client`.
- Database: change `prisma/schema.prisma`, then `pnpm prisma migrate dev --name <name>` (never hand-write migrations). Additive only (CLAUDE.md rule 9). Tests run against `<db>_test`.
- Tests: vitest `src/**/*.test.ts(x)` for web/server logic; jest + React Native Testing Library `mobile/src/**/*.test.ts(x)` for iOS logic; bug fixes include a reproducing test; new web flows get a Playwright spec in `e2e/` (backend mocked via `e2e/mockApi.ts`), new iOS flows a Maestro flow in `mobile/.maestro/` (don't run simulators).
- Never edit `mobile/ios/` by hand (generated by prebuild).
- **Dev preview for every new or changed iOS UI** (screen, sheet, paywall state, gallery state), so the owner can see it on the dev client without reaching it in real use:
  - Add an entry to `mobile/src/dev/previews.tsx` (`{ title: 'Paywall — out of credits', render: () => <Paywall … mock props /> }`), grouped by screen.
  - The list covers **only this PR's UI changes**: remove the entries left by earlier PRs (and mocks/imports only they used).
  - The list is shown by the dev-only route `mobile/src/app/dev/preview.tsx`; the route redirects home when `!__DEV__`.
  - **Every agent PR that changes the iOS app adds the floating "Preview" button**, UI change or not (with no new UI, the list holds whatever lets the owner check the change, e.g. a mock state showing new logic). It is removed before the PR merges to `main` (`main` never has it). Keep removal to one command:
    - The button is the self-contained `mobile/src/dev/DevPreviewButton.tsx` (renders nothing unless `__DEV__`, absolutely positioned above the tab bar, owns its styles; it stays on `main`, unused). Create it if missing.
    - The root layout `mobile/src/app/_layout.tsx` gets exactly two lines, each ending with the `DEV-PREVIEW` marker, and nothing else:
      `import { DevPreviewButton } from "@/dev/DevPreviewButton"; // DEV-PREVIEW`
      `<DevPreviewButton />{/* DEV-PREVIEW */}` right after `</Stack>` inside `ThemeProvider` (no space before the comment: inside a `View` it would render as a stray text string and crash).
    - Before merging: `bash scripts/agents/remove-dev-preview.sh` (deletes every `DEV-PREVIEW` line in `mobile/src/app/`), then `pnpm verify:mobile` and commit "Remove dev preview button".
  - The preview list uses plain text rows (`Pressable` + `Text`); real UI goes only inside an opened preview. Use mock data, never real purchases, credits or uploads.
  - If these files don't exist yet, create them in your PR (keep them small).
- **Web changes** need no preview code: the PR's Vercel preview deployment is the preview. Remember previews share the production database: never seed, migrate destructively or create test data there.
- Before a PR: `pnpm verify` (+ `pnpm verify:mobile` when `mobile/` changed) green; commits small with bulleted bodies referencing `#<issue>`.
